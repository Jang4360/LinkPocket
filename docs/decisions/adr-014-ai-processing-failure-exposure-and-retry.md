# ADR-014: AI 처리(요약·임베딩) 실패의 사용자 노출과 재시도 정책

- 날짜: 2026-07-27 / 상태: 확정
- 범주: 아키텍처
- 관련: plan-04-async-ai-pipeline(예정), [invariants.md](../product/invariants.md)("AI 실패가 저장 실패로 전파되지 않는다"), [ADR-011 결정 3](adr-011-safe-fetch-ssrf-timeout-retry.md)(재시도 가능/불가 구분 패턴)

## 문제 정의 (사람이 직접 정의 — 사용자 가치·품질 기준)

> 3. 일단 목록에 넣는게 맞아. 검색엔 안걸리지만 목록에 넣고 기존 요약을 보여주는 란에는 요약 생성 실패 라는 메시지를 넣는거지
> 4. 이미 백엔드상에서 재처리를 한것이기에 사용자에게 재처리 버튼으로 제공할 필요는 없다고 생각하고 다만 백그라운드 재처리도 추후에 최대 2번까지하고 실패하면 이미지나 다른 텍스트가 아닌 포맷으로 요약이 안된다고 생각하는게 맞는 것 같다
> (후속 확인) 400번대 에러는 뭘해도 똑같이 실패할 에러니 바로 fail fast하고 500 에러나 일시 장애 같은 경우에만 재시도하게 해줘.

요약·임베딩이 영구히 실패해도 Link는 목록에서 정상적으로 보여야 하고(삭제·숨김 없음), 요약 영역에만 실패를 알린다. 사용자에게 수동 재시도 UI는 필요 없다 — 백엔드가 알아서 처리한다. 다만 무한 재시도는 원하지 않고, 재시도해도 결과가 달라지지 않는 실패(형식 문제 등)는 재시도 없이 즉시 확정하고, 재시도로 회복 가능한 실패(API 일시 장애 등)만 제한된 횟수(최대 2회) 재시도한다.

## 가설

plan-03([ADR-011 결정 3](adr-011-safe-fetch-ssrf-timeout-retry.md))에서 이미 검증한 "재시도 가능/불가 사유 구분" 패턴을 AI 처리 단계에도 그대로 확장하면, fail-fast(불가 사유)와 제한 재시도(가능 사유)를 새 개념 없이 일관되게 구현할 수 있다.

## 대안 (선택지와 트레이드오프)

| 선택지 | 트레이드오프 |
|---|---|
| **재시도 불가 사유는 즉시 확정, 재시도 가능 사유만 최대 2회 카운트 후 영구 실패** (채택) | 콘텐츠 정책 거부 등 "다시 해도 뻔한" 실패는 헛되이 기다리지 않고 바로 "요약 생성 실패"로 확정해 사용자가 더 빨리 최종 상태를 본다. API 일시 장애 등 진짜 회복 가능한 경우만 재시도 예산(2회)을 쓴다 |
| 사유 구분 없이 claim 횟수(2회)만 카운트 | 구현은 더 단순하지만, 재시도해도 절대 안 되는 케이스도 여러 lease 주기(수 분)를 낭비한 뒤에야 실패로 확정된다 |

## 선택 (무엇을, 사람의 판단 근거)

**재시도 가능/불가 사유 구분 + 재시도 가능 사유만 최대 2회를 채택한다.** 사용자가 명시적으로 "400번대는 fail fast, 500번대·일시 장애만 재시도"로 확인했고, 이는 plan-03에서 이미 쓴 패턴과 동일한 모양이라 하네스 전체가 일관된다.

- **목록·상태 노출**: AI 처리가 영구 실패해도 Link는 목록에서 정상 노출되고 검색에서만 제외된다. 요약 필드에는 "요약 생성 실패"류 메시지를 채운다(필드를 비우거나 항목 자체를 숨기지 않는다).
- **재시도 예산**: 재시도 가능 사유(`SUMMARIZE_API_ERROR`, `EMBEDDING_API_ERROR`, `INDEX_WRITE_FAILED`)는 최대 2회, 재시도 불가 사유(`SUMMARIZE_CONTENT_REJECTED`, `CHUNKING_FAILED`)는 1회 시도 후 즉시 영구 실패로 확정한다.
- **재시도 트리거**: 사용자에게 수동 재시도 UI를 노출하지 않는다 — worker의 lease 기반 자동 재claim(ADR-012 결정 2)이 재시도 메커니즘 자체이고, 그 위에 이 ADR의 "횟수 상한"만 얹는다.

## 관찰 지표

- 재시도 가능 사유의 최종 성공률(1차/2차 시도 중 몇 %가 회복되는지)
- 영구 실패(`요약 생성 실패`)로 확정되는 Link 비율, 사유별 분포
- 재시도 불가 사유가 실제로는 회복 가능했던 사례(오분류) 발생 여부 — 사유 분류 자체의 정확도

## 결과 (구현·운영 후 채움)

미측정 — plan-04 구현 전.

## 재검토 조건

- 재시도 가능 사유의 2회 재시도 성공률이 낮게 관측되면(대부분 3회차부터 회복) 상한을 조정한다.
- 재시도 불가로 분류한 사유가 실제로는 종종 회복 가능하다고 관측되면(오분류) 분류 기준을 재검토한다.
