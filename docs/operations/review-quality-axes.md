# 리뷰 품질 축 체크리스트

> Claude가 게이트(`verify.sh`) 통과 후 계약 준수를 리뷰할 때 함께 확인하는 7축. "불변식 지켰나" 한 축만 보면 다른 실패가 샌다([development-loop.md](../development-loop.md) 소유권 표).

각 축은 리뷰 코멘트에 "어떤 근거로 판단했는지" 한 줄을 남긴다. 실패 시 차단(diff 반려)인지 보류(다음 task로 이월, 기록만)인지도 함께 표시한다.

| 축 | 확인할 것 | 실패 시 |
|---|---|---|
| 정확성 | AC·불변식이 계약 테스트 통과를 넘어 실제 코드 경로에서 지켜지는가 | 차단 |
| 보안·개인정보 | tenant 경계 강제, 비밀값·PII 노출 여부 | 차단 |
| 동시성·회복성 | 트랜잭션 경계, 재시도·부분 실패 시 상태가 계약대로인가 | 차단(위험 로직 트리거 해당 시) |
| 호환성 | 기존 API·DB 스키마·에러 코드 계약을 깨지 않는가 | 차단 |
| 성능·비용 | N+1, 불필요한 외부 호출 증가가 없는가 | 보류(측정 인프라 없으면 관찰 기록만) |
| 운영성 | 실패 시 원인을 로그·에러코드로 추적 가능한가 | 보류 |
| 범위(drift) | plan의 "허용 쓰기 경로" 밖 파일·무관한 변경이 섞였는가 | 차단 |

각 항목에서 반복적으로 잡히는 실패는 [mistake-ledger.md](mistake-ledger.md)에 기록해 승격 여부를 판단한다.
